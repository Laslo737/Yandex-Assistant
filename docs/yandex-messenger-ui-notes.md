# Yandex Messenger UI / Bot API Notes

Контекст: этот документ фиксирует практические наблюдения и подтвержденные правила по Yandex Messenger Bot API, которые уже повлияли на реализацию продукта. Если работа продолжается по `todo.md`, этот файл тоже считать частью обязательного контекста.

---

## 1. Форматирование текста в сообщениях

Подтверждено, что Yandex Messenger поддерживает markdown-подобное форматирование в `text` сообщения.

### Поддерживаемые стили
- жирный: `**текст**`
- курсив: `__текст__`
- зачеркнутый: `~~текст~~`
- подчеркнутый: `++текст++`
- inline code: `` `текст` ``
- ссылка: `[текст](url)`
- code block: triple backticks

### Практический вывод для проекта
- ключи задач можно безопасно встраивать как inline links формата `[IT-6911](https://tracker.yandex.ru/IT-6911)`;
- длинные URL внутри markdown могут ломать рендер и/или упираться в лимиты текста, поэтому для длинных query-links лучше использовать short redirect links через backend.

---

## 2. Ограничение длины text

Для `sendText` параметр `text` ограничен длиной `6000` символов.

### Практический вывод
- нельзя бездумно вшивать длинные query URLs в несколько markdown-ссылок внутри одного сообщения;
- для metric deep-links нужно использовать короткие redirect URLs через backend.

## 3. SuggestButtons — важное правило layout

### Подтвержденное правило API
`SuggestButtons` работает в двух режимах:

#### `layout: false`
- `buttons` должен быть **одномерным массивом** `InlineSuggestButton[]`
- кнопки идут в одну строку с переносом по правилам клиента

#### `layout: true`
- `buttons` должен быть **двумерным массивом** `InlineSuggestButton[][]`
- каждый вложенный массив — отдельная строка кнопок

### Важное следствие
Если передать:
- `layout: true`
- но `buttons` как одномерный массив

то payload становится невалидным, и кнопки могут вообще не отображаться.

### Практический вывод для проекта
- при включенном `layout: true` всегда передавать `buttons` как двумерный массив;
- текущая реализация в проекте использует раскладку по строкам через `chunkButtons(..., 2)`;
- если дальше потребуется UX-раскладка вида `1 кнопка на всю строку + дальше по 2`, это нужно реализовывать именно через структуру двумерного массива.

## 4. Директивы кнопок

Подтверждены важные типы директив:
- `send_message` — отправляет сообщение в чат от имени пользователя
- `server_action` — не пишет сообщение в чат, а отправляет событие боту
- `open_uri` — открывает URL в браузере
- `set_elements_state` — меняет состояние элементов интерфейса (`disabled`, `loading`)

### Практический вывод
Сейчас проект в основном использует `send_message`, но для более сильного UX в будущем можно применять:
- `open_uri` для безопасного открытия ссылок по кнопке, если это понадобится;
- `server_action` для более чистых сценариев без засорения чата текстом кнопки;
- `set_elements_state` для loading/disabled UX на время долгой обработки.

---

## 5. BotRequest / server_action

Если пользователь нажимает кнопку с директивой `server_action`, в update приходит `bot_request`.

### Практический вывод
Это потенциально полезно для будущих сценариев:
- navigation without chat noise;
- action buttons без отправки технических текстов в чат;
- более аккуратный conversational UX.

Сейчас это в продукте еще не используется как основной механизм, но стоит держать как следующий уровень эволюции интерфейса.

---

## 6. sendTyping

Подтвержден endpoint:
- `POST /bot/v1/messages/sendTyping/`

Требование:
- нужно указать ровно один target: `chat_id` или `user_id` или `login`

Таймаут эффекта:
- около `3` секунд

### Практический вывод
- typing нужно отправлять не просто перед `sendText`, а ideally до тяжелой бизнес-логики, если хотим заметный UX-эффект;
- текущая реализация уже умеет отправлять `sendTyping`, но при очень быстрых ответах пользователь может не успевать его заметить.

---

## 7. Короткие redirect links для продукта

Из-за лимита текста и длинных query URLs в проекте реализован backend short-link слой:
- endpoint: `/r/:token`
- token -> redirect в длинный Tracker URL

### Практический вывод
- для metric deep-links использовать short links;
- для прямых ссылок на конкретные задачи можно продолжать использовать обычные inline links, потому что они короткие.

---

## 8. Что помнить при будущей доработке кнопок

Если в будущем снова будем менять кнопки, обязательно помнить:

1. `layout: true` => только двумерный массив кнопок;
2. длинные тексты кнопок портят визуал, даже если layout валиден;
3. если нужен более clean UX, стоит рассмотреть:
   - короткие названия кнопок;
   - управляемую раскладку по строкам;
   - `server_action` вместо `send_message` для некоторых сценариев;
   - `set_elements_state` для loading/disabled UI.
