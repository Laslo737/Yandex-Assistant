## Исправленные ошибки и продуктовые решения

1. Изначально ошибочно грузился архив ради «Всего», а ACL делал GET каждой задачи:
   728 задач, timeout60,7сек/386HTTP. Сначала убран N+1: полные свежие auth-поля
   `_search` + прежний evaluator + request-local cache прав очередей; неполная
   проекция → канонический GET fallback. DENY/компоненты/fail-closed не ослаблялись.
2. Затем исправлен сам продуктовый смысл: **оперативные сценарии получают только
   незавершённые СРАЗУ из Tracker** — daily/ручной digest, «Мой день», «Моя команда»,
   риски, briefing. Закрытые/отменённые не нужны для их счётчиков или фокуса.
   Архивные «Всего» и дубли/ссылки на все статусы убраны. Старые внутренние total-поля
   остались aliases активных количеств, не архивными метриками.
3. Общие `active-issues.ts` и query builders используются для API и ссылок:
   **точный `Assignee: login@`**, terminal statuses по каталогу, URI escaping.
   В `_search` scope+status должны быть в **одном query**: top-level queue/filter
   перекрывают query. Query пагинируется через page/perPage, а не queue cursor.
   Нет каталога terminal statuses → ошибка, не fallback на весь архив.
4. «Изменения» — намеренное исключение: недавнее закрытие является событием.
   Явный анализ завершённой задачи по ключу также сохранён после проверки доступа.
5. «Спросить AI» скрыта из кнопок/приветствия как неготовый stub; рабочий AI-анализ
   отдельной задачи не отключён. Пользователи и first/last_seen аналитики хранятся
   бессрочно; события —90дней, уже удалённые записи не восстанавливаются.
6. Новые короткие metric-links постоянные SQLite и переживают рестарт; прежние
   in-memory токены восстановить нельзя.

## С чего продолжить

1. Проверить первую scheduled-доставку и сообщение/ссылки глазами, не объявлять
   успех только по health или ручному build. Проверить отписку/повторное включение.
2. Добавить digest/short-links в consistent backup/rotation и isolated restore;
   существующий installer не переустанавливать вслепую.
3. До расширения allowlist — небольшой пилот и замеры. Не ставить `*`, не импортировать
   всех из analytics.users (там ранее было2 различных аккаунта, не оба получатели).
4. ACL компонентов/webhook/mixed load остаются открытыми вопросами. В интерактивном
   «Моём дне» сохраняется ранее согласованное упрощение per-issue ACL, но точный
   assignee ID проверяется; в остальных рабочих сводках ACL обязателен.
5. Глобальный поиск/новые Q&A/перепаковка остальных сценариев не являются автоматически
   согласованной следующей работой. Не расширять scope без продуктового основания.

исправления не путать с доказательством отсутствия любых ошибок во всём продукте.
